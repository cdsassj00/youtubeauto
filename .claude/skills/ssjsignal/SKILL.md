# ssjsignal — SIGNAL 디자인 단일 HTML 슬라이드

`ssjhtmlvideo` 의 SIGNAL 화면 디자인을 그대로 쓰되, **나레이션·TTS·영상 렌더를 걷어낸** 버전이다.
결과물은 **HTML 파일 하나**다. 브라우저로 열면 바로 발표할 수 있고, 메일에 첨부해도 되고,
인쇄(Ctrl+P)로 PDF 가 나온다. 외부 요청이 없어 인터넷 없이도 똑같이 보인다.

## ssjhtmlvideo 와 무엇이 다른가

| | ssjhtmlvideo | **ssjsignal (이 스킬)** |
|---|---|---|
| 결과물 | MP4 영상 | HTML 파일 하나 |
| 나레이션 | ElevenLabs TTS + 자막 | 없음 |
| 화면 전환 | `__setTime(t)` 프레임 렌더 | 키보드/클릭 (CSS 트랜지션) |
| 필요한 것 | Playwright, ffmpeg, API 키 | **없음** (node 만) |
| 걸리는 시간 | 수 분~수십 분 | 1초 미만 |
| 쓸 때 | 유튜브에 올릴 때 | 발표·공유·문서로 남길 때 |

**디자인(색·타이포·레이아웃·슬라이드 5종)은 완전히 같다.** 그래야 같은 내용을 영상으로도,
슬라이드로도 낼 때 결이 어긋나지 않는다.

## 쓰는 법

```bash
node build.mjs deck.json out.html            # 기본 (폰트는 CDN, 없으면 시스템 폰트)
node build.mjs deck.json out.html --embed    # 폰트를 파일 안에 넣어 완전 오프라인 (약 +2.7MB)
node build.mjs deck.json out.html --accent "#4da3ff"   # 액센트 색 변경
```

`--embed` 는 `../ssjhtmlvideo/assets/` 의 폰트를 base64 로 심는다. 그 폴더가 없으면
거기서 `node fetch-assets.mjs` 를 먼저 돌린다. 메일 첨부·USB 전달처럼 네트워크를 믿을 수
없을 때만 쓰고, 평소에는 기본값이 낫다(파일이 20KB 안팎으로 가볍다).

## 조작

| 키 | 동작 |
|---|---|
| `→` `↓` `Space` `PageDown` · 화면 클릭 | 다음 |
| `←` `↑` `PageUp` | 이전 |
| `Home` / `End` | 처음 / 끝 |
| `F` | 전체화면 |
| `P` | 인쇄 보기(모든 슬라이드를 한 장씩 세로로) → Ctrl+P 로 PDF 저장 |
| 숫자 키 | 그 번호 슬라이드로 |

## deck.json 형식

최상위는 배열이거나 `{ header, accent, slides }` 객체다.

```json
{
  "header": "<b>반도체</b> · 왜 지금인가",
  "accent": "#2ee87a",
  "slides": [ { "type": "claim", "kicker": "OPENING", "claim": "데이터가 <em>주인공</em>이다" } ]
}
```

`header` 는 좌상단에 계속 떠 있는 챕터 라벨이다(HTML 태그 허용 — `<b>`로 앞부분만 강조).

### 슬라이드 5종

**claim** — 한 문장이 화면을 가득 채운다. 전환점·단언·표지에 쓴다.
```json
{ "type": "claim", "kicker": "OPENING", "claim": "생맥주도 <em>공장맥주</em>다", "lead": "다른 건 맥주가 아니라 포장이다" }
```
`<em>` 으로 감싼 부분만 액센트 색이 된다. 한 슬라이드에 한 군데만 쓴다.

**big** — 거대한 숫자 하나. 이 디자인의 핵심 화면이다.
```json
{ "type": "big", "kicker": "SERVING", "value": "2~4", "unit": "°C", "sub": "생맥주 서빙 온도", "lead": "이 구간을 벗어나면 향이 닫힌다" }
```

**convert** — A → B 변환·전후 비교.
```json
{ "type": "convert", "from": "몇 달", "fromLabel": "매대에서", "to": "며칠", "toLabel": "케그에서", "lead": "차이는 시간이다" }
```

**metrics** — 지표 카드 2~4개. `items` 는 `[라벨, 값, 각주]` 배열.
```json
{ "type": "metrics", "kicker": "세 가지 변수",
  "items": [["살균", "열처리", "향이 눌린다"], ["시간·빛", "몇 달", "홉이 분해된다"], ["따르기", "거품층", "산소를 막는다"]] }
```
5개 이상 넣지 마라 — 카드가 작아져 숫자가 안 읽힌다.

**nodes** — 관계도. `points` 는 `%` 좌표, `links` 는 점 인덱스 쌍, `hi` 는 강조할 점들.
```json
{ "type": "nodes", "kicker": "한 발효조에서",
  "points": [{"x":50,"y":18,"label":"발효조"},{"x":22,"y":62,"label":"케그"},{"x":78,"y":62,"label":"캔·병"}],
  "links": [[0,1],[0,2]], "hi": [1] }
```

## 이걸 어기면 디자인이 무너진다

1. **화면에 요소 1~3개.** 여백이 이 디자인의 절반이다. 채우려 들면 그냥 흔한 다크 테마가 된다.
2. **액센트는 한 색, 한 군데.** 초록이 여기저기 있으면 아무 데도 눈이 안 간다. 슬라이드마다
   "제일 중요한 것 하나"에만 쓴다.
3. **claim 은 22자 안쪽.** 넘으면 글자가 줄어들어 임팩트가 사라진다. 길면 `lead` 로 내린다.
4. **숫자를 문장에 숨기지 마라.** 숫자가 있으면 `big` 이나 `metrics` 로 꺼내 크게 쓴다.
   그러라고 만든 디자인이다.
5. **kicker 는 영문 대문자 한두 단어.** 라벨이지 문장이 아니다.

## 원본과 다른 점 (알고 있어야 할 것)

영상판은 `__setTime(t)` 으로 시간을 못 박아 모든 움직임을 t 의 함수로 직접 계산한다.
CSS 트랜지션을 쓰면 프레임을 점프시킬 때 전환이 잘리기 때문이다. **여기서는 그 제약이 없다** —
사람이 실시간으로 넘기므로 CSS 트랜지션이 오히려 정확하고 코드도 짧다. 그래서 요소 등장은
CSS `transition-delay` 로 계단식으로 처리했다. 같은 디자인이지만 움직이는 방식은 다르다.

영상판에 있던 하단 자막(`#cap`)과 `say`/`spoken` 필드는 여기 없다. deck.json 에 남아 있어도
조용히 무시하므로, 영상용 덱을 그대로 넣어도 슬라이드가 나온다.
