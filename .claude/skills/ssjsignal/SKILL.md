# ssjsignal — SIGNAL 디자인 단일 HTML 슬라이드

`ssjhtmlvideo` 의 SIGNAL 화면 디자인을 그대로 쓰되, **나레이션·TTS·영상 렌더를 걷어낸** 버전이다.
결과물은 **HTML 파일 하나**다. 브라우저로 열면 바로 발표할 수 있고, 메일에 첨부해도 되고,
인쇄(Ctrl+P)로 PDF 가 나온다. 외부 요청이 없어 인터넷 없이도 똑같이 보인다.

## ssjhtmlvideo 와 무엇이 다른가

| | ssjhtmlvideo | **ssjsignal (이 스킬)** |
|---|---|---|
| 결과물 | MP4 영상 | HTML 파일 하나 |
| 나레이션 | ElevenLabs TTS + 자막 | 없음 |
| 화면 전환 | `__setTime(t)` 프레임 렌더 | 키보드/클릭 (CSS 트랜지션) |
| 필요한 것 | Playwright, ffmpeg, API 키 | **없음** (node 만) |
| 걸리는 시간 | 수 분~수십 분 | 1초 미만 |
| 쓸 때 | 유튜브에 올릴 때 | 발표·공유·문서로 남길 때 |

**디자인(색·타이포·레이아웃·슬라이드 5종)은 완전히 같다.** 그래야 같은 내용을 영상으로도,
슬라이드로도 낼 때 결이 어긋나지 않는다.

## 쓰는 법

```bash
node build.mjs deck.json out.html            # 기본 (폰트는 CDN, 없으면 시스템 폰트)
node build.mjs deck.json out.html --embed    # 폰트를 파일 안에 넣어 완전 오프라인 (약 +2.7MB)
node build.mjs deck.json out.html --accent "#4da3ff"   # 액센트 색 변경
```

`--embed` 는 `../ssjhtmlvideo/assets/` 의 폰트를 base64 로 심는다. 그 폴더가 없으면
거기서 `node fetch-assets.mjs` 를 먼저 돌린다. 메일 첨부·USB 전달처럼 네트워크를 믿을 수
없을 때만 쓰고, 평소에는 기본값이 낫다(파일이 20KB 안팎으로 가볍다).

## 조작

| 키 | 동작 |
|---|---|
| `→` `↓` `Space` `PageDown` · 화면 클릭 | 다음 |
| `←` `↑` `PageUp` | 이전 |
| `Home` / `End` | 처음 / 끝 |
| `F` | 전체화면 |
| `P` | 인쇄 보기(모든 슬라이드를 한 장씩 세로로) → Ctrl+P 로 PDF 저장 |
| 숫자 키 | 그 번호 슬라이드로 |

## deck.json 형식

최상위는 배열이거나 `{ header, accent, slides }` 객체다. `header` 는 좌상단에 계속 떠 있는
챕터 라벨이다(HTML 태그 허용 — `<b>`로 앞부분만 강조).

```json
{ "header": "<b>AI 에이전트</b> · 도입 실무", "accent": "#2ee87a", "slides": [ ... ] }
```

## 슬라이드는 두 갈래다

**임팩트형** — 화면에 요소 1~3개. 여백이 넓다. 표지·전환점·핵심 수치에 쓴다.
영상판에서 그대로 가져온 화면이다.

**밀도형** — 제목 줄이 위에 서고 본문이 캔버스를 채운다. 발표·강의용으로 추가했다.
40장짜리 강의안을 임팩트형만으로 만들면 내용이 안 들어가고 계속 비어 보인다.
**실제 강의안은 밀도형이 7할, 임팩트형이 3할 정도가 맞다.**

### 밀도형 (발표·강의용)

공통 필드: `heading`(제목, 필수) · `kicker`(위의 작은 라벨) · `sub`(제목 아래 설명 한두 문장) ·
`note`(맨 아래 옅은 한 줄 — 출처·단서).

**points** — 이 스킬에서 가장 많이 쓸 화면. 항목은 `"문자열"` 또는 `["요지", "설명"]`.
```json
{ "type": "points", "kicker": "판단 기준", "heading": "네 가지를 모두 만족할 때만 간다",
  "sub": "하나라도 아니오면 더 단순한 구조가 낫다.",
  "items": [["복잡성", "여러 단계이고 절차를 사전에 명세하기 어렵다"],
            ["가치", "결과물이 지연과 비용을 정당화한다"]],
  "note": "출처 · 사내 파일럿 12건" }
```
★설명을 붙여라★ 요지만 나열하면 키워드 슬라이드가 되고, 그게 바로 "밀도가 없다"는 상태다.
3~5개가 적당하고 6개를 넘기면 글자가 작아진다.

**table** — 강의안에서 두 번째로 많이 쓴다. 첫 열이 굵게 강조된다.
```json
{ "type": "table", "heading": "세 갈래를 무엇으로 가르는가",
  "columns": ["구조", "제어 주체", "적합한 일"],
  "rows": [["단일 호출", "코드", "분류 · 요약"], ["에이전트", "모델", "탐색적 작업"]] }
```
열 4개, 행 6개까지. 셀은 짧게 — 문장을 넣으면 표가 무너진다.

**split** — 둘을 맞세운다. 각 칸이 제목과 목록을 가진다. 오른쪽 칸이 액센트 색이다.
```json
{ "type": "split", "heading": "현장에서 터지는 것", "vs": "대응",
  "left":  { "title": "증상", "items": [["무한 루프", "같은 도구를 계속 호출"]] },
  "right": { "title": "방어", "items": [["턴 상한", "N회 넘으면 중단"]] } }
```

**steps** — 절차. 가로로 늘어놓고 화살표로 잇는다. 3~4개가 적당(5개부터 좁아진다).
```json
{ "type": "steps", "heading": "한 번에 가지 않는다",
  "items": [["수작업 관찰", "사람이 어떻게 하는지 3건을 적는다"], ["단일 호출", "한 단계만 자동화"]] }
```

**agenda** — 목차. `current`(0부터)를 주면 그 항목만 밝게 표시된다. 장이 바뀔 때마다 재사용한다.

**code** — `filename`, `code`. 줄바꿈은 `\n`. 18줄까지 들어간다.

### 임팩트형

**claim** — 한 문장이 화면을 채운다. `<em>`으로 감싼 부분만 액센트 색(한 군데만).
22자 넘으면 `lead` 로 내려라.
```json
{ "type": "claim", "kicker": "OPENING", "claim": "에이전트는 <em>도구</em>가 아니라 절차다", "lead": "..." }
```

**big** — 거대한 숫자 하나. `value`, `unit`, `sub`, `lead`.

**convert** — A → B. `from`, `fromLabel`, `to`, `toLabel`.

**metrics** — 지표 카드 2~4개. `items` 는 `[라벨, 값, 각주]`.

**nodes** — 관계도. `points`(`%` 좌표 + label), `links`(점 인덱스 쌍), `hi`(강조할 점).

**quote** — 인용. `quote`, `by`.

## 이걸 어기면 무너진다

1. **밀도형에는 설명을 붙여라.** `["복잡성"]` 이 아니라 `["복잡성", "여러 단계이고 절차를 사전에
   명세하기 어렵다"]`. 요지만 나열하면 읽을 게 없는 키워드 판이 된다.
2. **액센트는 한 색, 한 군데.** 초록이 여기저기 있으면 아무 데도 눈이 안 간다.
3. **임팩트형을 남발하지 마라.** 강의안에서 claim 이 연속 3장이면 내용이 없다는 뜻이다.
   장 전환에만 쓰고, 본론은 points·table·split 로 간다.
4. **한 슬라이드에 한 주제.** 항목이 7개를 넘으면 슬라이드를 쪼개라 — 글자를 줄이지 말고.
5. **kicker 는 짧은 라벨.** 문장이 아니다.
6. **숫자는 문장에 숨기지 말고 `big`·`metrics` 로 꺼내라.** 그러라고 있는 화면이다.

## 넘치는지 확인하는 법

캔버스는 1920×1080 으로 고정돼 있고 창 크기에 맞춰 통째로 축소된다(어느 화면에서도
줄바꿈이 같다). 내용이 많아 넘치면 화면 밖으로 잘리므로, 새 덱을 만들면 한 번 확인해라.
밀도형의 본문 하단은 996px, 우측은 1824px 가 한계다.

★확인할 때 전환이 끝나기를 기다려라★ 등장 애니메이션 중에 재면 씬 16px + 요소 14px 이
더해져 없는 넘침이 30px 씩 잡힌다(실제로 그렇게 두 번 헛짚었다).

## 원본과 다른 점 (알고 있어야 할 것)

영상판은 `__setTime(t)` 으로 시간을 못 박아 모든 움직임을 t 의 함수로 직접 계산한다.
CSS 트랜지션을 쓰면 프레임을 점프시킬 때 전환이 잘리기 때문이다. **여기서는 그 제약이 없다** —
사람이 실시간으로 넘기므로 CSS 트랜지션이 오히려 정확하고 코드도 짧다. 그래서 요소 등장은
CSS `transition-delay` 로 계단식으로 처리했다. 같은 디자인이지만 움직이는 방식은 다르다.

영상판에 있던 하단 자막(`#cap`)과 `say`/`spoken` 필드는 여기 없다. deck.json 에 남아 있어도
조용히 무시하므로, 영상용 덱을 그대로 넣어도 슬라이드가 나온다.
