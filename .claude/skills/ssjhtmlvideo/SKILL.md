# ssjhtmlvideo — HTML 화면 + 나레이션으로 만드는 설명 영상

브라우저로 그린 화면을 **프레임 단위로 캡처**하고, **각 문장의 TTS 오디오 길이만큼 그 화면을 머물게** 해서
나레이션과 화면이 정확히 맞는 MP4를 만든다. 실시간 화면 녹화가 아니라 결정적 렌더라 버벅임이 없다.

## 언제 쓰나
- 뉴스·발표자료·문서를 유튜브 설명 영상으로 바꿀 때
- 숫자·벤치마크·비교가 있는 내용을 시각적으로 정리할 때
- 나레이션에 맞춰 카메라가 도식을 따라가는 영상이 필요할 때

## 핵심 원리 (이걸 어기면 결과가 나빠진다)

1. **나레이션이 타임라인의 주인이다.** 각 비트(슬라이드 또는 도식의 한 단계)를 TTS 해서
   나온 **오디오 길이 = 그 화면이 머무는 시간**. 그래서 싱크가 절대 밀리지 않는다.
2. **CSS 트랜지션/애니메이션을 쓰지 말 것.** 프레임 렌더는 시간을 점프시키는데 CSS 는 실시간 기준이라
   전환이 잘려 툭툭 끊긴다. 모든 애니메이션은 `__setTime(t)` 안에서 **t 의 함수로 직접 계산**한다.
3. **자막은 짧게 쪼개 한 줄씩.** 긴 문장을 통째로 띄우면 화면을 가린다. 문장부호로 나누고 30자에서 한 번 더 자른다.
4. **자막(`say`)과 발음(`spoken`)을 분리한다.**
   - `say`: 화면에 뜨는 자막 — 제품명·숫자는 영어/아라비아 숫자 그대로 (`Opus 4.8`, `$25`, `ARC-AGI 3`)
   - `spoken`: 성우가 읽을 텍스트 — 한글 발음으로 풀어 씀 (`오퍼스 사 점 팔`, `이십오 달러`, `아크 에이지아이 쓰리`)
   - `spoken` 이 없으면 `say` 를 읽는다. 숫자·영문이 있으면 반드시 `spoken` 을 쓴다.
5. **장식보다 여백과 데이터.** 화면에 요소 1~3개, 숫자를 크게. 떠다니는 도형으로 채우지 않는다.

## 스타일 3종

| 스타일 | 파일 | 특징 | 어울리는 내용 |
|---|---|---|---|
| `signal` | `engines/deck-signal.js` | 딥블랙 + 단일 액센트 + 거대 숫자 + 모노 라벨. 평면. | 벤치마크·수치·비교가 많은 기술 뉴스 |
| `signal3d` | 같은 파일 + `SPACE3D` | SIGNAL 디자인 그대로 3D 깊이 공간을 카메라가 통과. 텍스트는 DOM 이라 선명. | 임팩트가 필요한 발표·출시 소식 |
| `deck3d` | `engines/deck-timed.js` | Three.js 3D 공간에 카드와 기하 도형, 카메라가 도식을 추적. | 개념·흐름 설명, 단계가 있는 주제 |

## 제작 순서

1. **자료 확보** — 주제의 사실·수치를 먼저 모은다(웹 문서가 있으면 읽고, 없으면 사용자에게 받는다).
   추상적 컨셉만 나열하지 말고 **실제 수치와 고유명사**를 쓴다.
2. **deck.json 작성** — 스키마는 `references/deck-schema.md` 참고. 슬라이드마다 `say`/`spoken`.
   - 목표 길이(분) × 460자 × 배속 = 필요한 `say` 총 글자 수. 미달하면 영상이 짧아진다.
   - 10분 영상이면 최소 20~26 슬라이드, 각 `say` 는 2~4문장(120~220자).
3. **에셋 준비**(최초 1회) — `node fetch-assets.mjs` 로 폰트·Three.js 를 내려받는다.
4. **렌더** — `ELEVENLABS_API_KEY=... ELEVENLABS_VOICE_ID=... node render.mjs deck.json out.mp4`
   - 환경변수: `W`/`H`(기본 1920×1080), `FPS`(기본 24), `NARRATION_SPEED`(기본 1, 1.12 정도가 듣기 좋다)
5. **확인** — 길이·발음·자막·싱크를 프레임 몇 장 뽑아 점검하고, 필요하면 deck 을 고쳐 다시 렌더한다.

## 파일

- `engines/deck-signal.js` — SIGNAL / SIGNAL 3D 엔진 (DOM/CSS, `window.SPACE3D` 로 3D 전환)
- `engines/deck-timed.js` — DECK3D 엔진 (Three.js, 전역 `THREE` 필요)
- `render.mjs` — TTS → 길이 측정 → HTML 조립 → 프레임 스트리밍 → mp4 (핵심 도구)
- `fetch-assets.mjs` — Pretendard / JetBrains Mono / Three.js 내려받기
- `references/deck-schema.md` — 슬라이드 타입별 필드 전체
- `examples/` — 실제로 만든 deck 예시

## 주의

- 렌더는 실시간이 아니라 프레임마다 캡처하므로 **10분 영상이면 수십 분** 걸린다. 백그라운드로 돌린다.
- Chromium 경로를 코드에 하드코딩하지 말 것 — CI 와 로컬 위치가 다르다(`render.mjs` 는 자동 처리).
- 유튜브 미드롤 광고를 넣으려면 **8분 이상**이어야 한다. 10분을 목표로 잡는다.
